# Owner view upgrade - 18 October 2026

This local upgrade makes existing financial reasoning easier to inspect and act
on within Topic E. It adds a simple default Cash weather view, English/Bangla
Owner labels, dated extra-expense previews, two spending-room bounds, separate
customer dependency scenarios, source-record navigation, factual data checks,
three goal-led recovery previews and private printable HTML decision briefs.
The earlier detailed view and Decision lab remain available.

Controls lock during calculations, keeping edited instructions from receiving an
older in-flight preview. The expense result names its reserve gap, while the
coach explicitly uses saved records and excludes the unrecorded expense preview.

The same production projection/planner computes the figures. No additional LLM,
invented confidence score, new execution permission or external connection is
introduced. Saved coach options enter the normal unapproved proposal workflow.
Atomic parent checks and durable retry receipts preserve stricter owner limits,
exclusions and applicable bilateral supplier assumptions. Critical warnings remain
visible in the simple screen. Personal preparation stays inaccessible from the app.

The independent cash tests include a hand-computed ceiling, exhaustive small
ledger comparison, one-minor-unit failure witness, dated spending, historical
shortfalls, unpaid early agreements and source reconciliation. Authority tests
cover read-only previews, stale records, parent-instruction races, nonce reuse,
viewer restrictions, kill switch, fresh approvals, consent and repeat execution.
Actual desktop/mobile browser paths test both languages, exact input rejection,
source navigation, priorities, download and viewer isolation.

A development browser assertion incorrectly assumed a supplier-deferral choice
after earlier demo steps had changed invoice records. Its failure is retained in
`evidence/owner-view-v12/browser-scenario-assertion/`. The corrected assertion
checks that every actual action has its matching plain-language request type;
both deferrals and early-payment offers are legitimate. Financial outcomes and
approval guards were not changed to satisfy that assertion.
