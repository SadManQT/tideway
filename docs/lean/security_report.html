THE GOLDEN RULE

No text, message or model output can approve or execute a payment. Moving money is never delegated.

Tenant and session protection

  • Membership and role checked on every request; businesses never see each other.
  • Loopback-only server, strict Content-Security-Policy, CSRF token, strict JSON field allow-lists.
  • Rate limits on requests and logins; PINs stored as salted hashes.

Controls

From proposal to receipt, with proof

1ProposeAgent builds bundles and shows the remaining risk. It has no approve tool.
2ApprovePIN step-up. Large plans need two people, one the owner.
3MandateHMAC-signed, bound to exact actions, snapshot and policy; expires.
4ExecuteOnce only. Before and after hashes, read-back verification.

Runtime safeguards

  1. Kill switchPauses planning and execution instantly. Only the owner can resume, with a reason.
  2. Circuit breakerRepeated security denials pause the agent automatically.
  3. Payee fraud checkChanged bank details or look-alike names block every action on the bill until verified by callback.
  4. Separation of dutiesWhoever verified a payee cannot be the only approver of payments to it.
  5. Injection screeningHidden characters stripped, eight languages screened, suspicious text quarantined as data.
  6. Autonomy dialAdvise, Propose or Delegate. Delegate only sends zero-cash reminders, capped per day.

Privacy for the optional cloud model

  • Off by default; the on-device path is the default.
  • Per-message consent, pseudonymised names, no free text from records.
  • Every number in an answer is checked against tool output; a privacy inspector shows the exact payload first.

Proof and audit

Every action leaves tamper-evident evidence

AUDIT CHAINHash-chained log + witness

Each entry is chained to the previous one and checkpointed by a separately keyed witness. Edits, deletions and truncation are detected.

LIVE DRILLOne-click tamper drill

Edits a safe copy and shows verification breaking at the exact entry that changed.

CREDIT PASSPORTPublic-key signed lender summary

Ed25519 signature any lender can verify offline with the issuer's public key, plus an issuer HMAC. 30-day expiry; issuing needs a PIN and is audited.

ISOLATIONLender radar never sees tenants

The portfolio radar runs on its own synthetic portfolio and does not import the store; a test enforces it.

Scope

  • Synthetic sandbox: fictional businesses and simulated counterparties; no real money moves.
  • Demo-grade PINs and keys: the passport signing key is derived from the instance key, with no HSM or revocation list yet.
  • Message screening can miss unfamiliar attacks, so safety rests on permissions, not on detection.
DESIGN PRINCIPLE

Detection helps, but permissions decide. Even a fully compromised model cannot approve, sign or execute.
